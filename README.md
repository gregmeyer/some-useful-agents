# some-useful-agents

A local-first agent playground. Author agents as composable flows, run them from the CLI or MCP, schedule them on cron, chain them into multi-step pipelines with branching and loops, and manage everything from a web dashboard.

MIT-licensed. Published to [npm](https://www.npmjs.com/search?q=%40some-useful-agents).

![Home: your notebooks and what needs you today](docs/images/home.png)

## What you get

**Agents**
- **Agents as flows** — each agent is a DAG of nodes: shell commands, `llm-prompt` model calls, named tools, `goal` nodes, and `ask` nodes. Flow control (conditional, switch, loop, agent-invoke, branch, end, break) lets agents make decisions and run sub-agents. Reference: [docs/flows.md](docs/flows.md).
- **Goal agents** — a `goal` node gives a model a goal, tools and a budget (turns, time), and it works until it can answer. Build from goal drafts one for open-ended asks. See [docs/goal-agents.md](docs/goal-agents.md).
- **Agents as tools** — put `agent:<id>` in a node's `tools:` and the model can call another agent as a sub-run (up to 3 levels deep, no cycles). See [docs/agents-as-tools.md](docs/agents-as-tools.md).
- **Conversations** — talk to any agent with a text input and follow up: the agent's **Chat** tab (replies stream in live over a WebSocket), `sua agent chat`, or MCP `run-agent` with a `sessionId`. See [docs/conversations.md](docs/conversations.md).
- **Memory** — `memory: true` gives an agent notes that persist between runs, recalled automatically, with `memory-save` / `memory-search` / `memory-forget` tools. See [docs/memory.md](docs/memory.md).
- **Ask a person** — an `ask` node, or the `ask-human` tool in an llm or goal node, pauses the run and puts the question in your inbox; answering resumes it. See [docs/ask-a-person.md](docs/ask-a-person.md).
- **Behaviors** — write down how an agent should conduct itself as an [Agent Behavior](docs/behaviors.md) spec, and optionally let it steer the agent.

**Models and tools**
- **Many providers, with a fallback waterfall** — Claude, Codex, on-device Apple Foundation Models, or any **OpenAI-compatible endpoint** for local / self-hosted models (llama.cpp, LM Studio, Ollama, vLLM, …). Reorder, add and enable/disable providers at `/settings/llm`; on a classified failure (down, timeout, quota, 401, 429) the run falls through to the next one. Pin per node or agent with `provider:`. Claude and Codex get a node's `tools:` over a short-lived local MCP endpoint; OpenAI-compatible endpoints get them natively. A local model server can run as a `sua daemon` service. See [docs/llm-providers.md](docs/llm-providers.md).
- **Built-in tools** — `shell-exec`, `http-get`, `http-post`, `file-read`, `file-write`, `json-parse`, `json-path`, `template`, `csv-to-chart-json`, web fetch and scrape, `board-read` / `board-place`, and more; plus MCP-imported tools, your own tools, and tools generated by integrations. Every tool call is recorded on the run page. See [docs/tools.md](docs/tools.md).
- **Integrations** — connect a data source or service at `/tools?tab=integrations` and get tools for free: CSV / Postgres / SQLite generate find/count tools, Gmail connects via OAuth, and `notify` handlers can use saved Slack / webhook / file destinations. See [docs/integrations.md](docs/integrations.md).
- **MCP servers** — paste a Claude Desktop / Cursor `mcpServers` config, pick which tools to import, and runs can call them like any other tool. Manage servers at `/tools?tab=servers`. See [docs/mcp.md](docs/mcp.md).

**Control and safety**
- **Tool policies** — allow/deny rules checked on every tool call, by tool, resource (URL, path, command) and agent source. Edit and test them in **Settings → Policies** ("Would this be allowed?"). See [docs/tool-policies.md](docs/tool-policies.md).
- **Cost and spend limits** — every run records its tokens and cost; see them per run, in **Settings → Usage**, or with `sua usage`. Cap a run or an agent's day with `spendLimit: { perRunUsd, perDayUsd }`. See [docs/cost.md](docs/cost.md).
- **Secrets store** — encrypted at rest (AES-256-GCM, scrypt). Protect it with a passphrase, or use the zero-friction fallback keyed off a stable local machine key. Dashboard CRUD with redaction.
- **Run reliability** — per-node `timeout:` and agent `timeoutSec:` ceilings; a reaper fails runs orphaned by a restart and kills their leftover processes; cancel escalates to SIGKILL. See [docs/SECURITY.md](docs/SECURITY.md).

**Triggers**
- **Scheduling** — cron on any agent; `/scheduled` lists every scheduled agent with Pause / Resume / Activate, and Pulse shows a red scheduler tile if agents are scheduled but the scheduler isn't running. A Temporal provider is available for durable runs. See [docs/temporal.md](docs/temporal.md).
- **Inbound webhooks** — start an agent from another service with `POST /hooks/<agent>`: a per-agent secret (or a GitHub signature), body-to-input mapping and filters. See [docs/webhooks.md](docs/webhooks.md).
- **MCP server (outbound)** — expose your agents to Claude Desktop and other MCP clients; `run-agent` also holds conversations (`message` + `sessionId`), `board-read` / `board-place` arrange boards, and `build-board` builds one from a request. See [docs/mcp.md](docs/mcp.md).

**Notebooks: goals you keep**
- **Notebooks** — a goal sua keeps for you over time: a car to buy, a job to find, a place to rent. Say it in a sentence and sua drafts the notebook (limits, what "done" means, what to note for each option, stages, which agents search); then it searches, files what it finds as options with their facts and pictures, and tracks them through a funnel to a decision. Talk to sua about it in its own conversation. See [docs/notebooks.md](docs/notebooks.md).

**Seeing results**
- **Dashboard** — manage agents, tools, runs, secrets, variables and settings in the browser. **Home** shows your notebooks and what needs you today; **Pulse** (`/pulse`) is your board of agent tiles, and every tile has a **Run** button. Visual DAG editor with a wiring mode, run pages with node-by-node detail, budgets and tool calls. See [docs/dashboard.md](docs/dashboard.md).
- **Widgets, drawn with A2UI** — an agent can describe its widget as an [A2UI](https://a2ui.org) `view:` (declared in YAML, or generated by a node each run), and it's drawn on the run page, its Pulse tile, dashboards, inbox threads, and as a chat reply whose buttons send the next message. Existing output widgets and Pulse templates are drawn the same way, with sorting, filtering, paging, tabs and run-in-place forms in the browser. See [docs/a2ui-views.md](docs/a2ui-views.md) and [docs/output-widgets.md](docs/output-widgets.md).
- **Boards as canvases** — Pulse and every dashboard are drawn as one A2UI canvas: sections, responsive grids, rows, tabs and cards, with each agent's tile drawn inside by its own view. Arrange it in an outline editor (**✎ Arrange**), let the layout planner propose one (**✨ Suggest a layout**), or let an agent do it with the `board-read` / `board-place` tools. Layouts are stored by the dashboard, versioned and undoable. See [docs/boards.md](docs/boards.md).
- **Build a board from a request** — describe a board (**＋ New board**, Ask sua, or MCP `build-board`) and sua picks your agents, lays it out, runs every tile and tells you in the inbox when it's ready; agents for anything not covered are drafted and wait for your one approval. See [docs/boards.md](docs/boards.md#build-a-board-from-a-request).
- **Brand theme** — one theme for every page, board and tile: a preset, then your colours for dark and light mode, fonts, corner radius and tile accents, in **Settings → Appearance → Brand**. See [docs/brand.md](docs/brand.md).
- **Dashboards and packs** — named boards over your agents; packs install curated agents and dashboards together (the `Starter` pack ships with sua). Browse at `/packs`.

**Building agents**
- **Build from a goal** — describe what you want and sua drafts the agents (a goal node for open-ended asks, a fixed flow for repeatable ones), shows each draft's shape and **why**, lets you switch the shape and **Try it** before keeping it. See [docs/build-from-goal.md](docs/build-from-goal.md).
- **Suggest improvements** — one-click review of an agent's YAML by the built-in `agent-analyzer`, with a diff you can apply.
- **Global variables** — plain-text values every agent can use (`/settings/variables` or `sua vars`); `$NAME` in shell, `{{vars.NAME}}` in prompts.
- **40+ bundled examples** — from "hello world" to MCP-driven graphics, installed by `sua init`. The dashboard opens new users on **Start here** (`/start`): four agents, one per pattern (research something, watch something, draft something, work it out).

## Quick start

```bash
npm install -g @some-useful-agents/cli
mkdir my-agents && cd my-agents
sua init                    # creates project + installs example agents
sua agent run hello         # run your first agent
sua dashboard start         # open the web dashboard
```

Prefer `npx`? `npx @some-useful-agents/cli@latest init` works without installing globally.

## CLI commands

### Agents

```bash
sua agent list                          # all agents (examples + local)
sua agent new                           # interactive scaffold
sua agent run <name>                    # run once
sua agent run <name> --input K=V        # supply inputs (-i for short)
sua agent chat <name>                   # talk to an agent and follow up (-m "…" for one message)
sua agent webhook <name> --on           # start it from another service: POST /hooks/<name>
sua agent reimport <path>               # refresh agent(s) in DB from on-disk YAML
```

### Memory, cost and policies

```bash
sua memory list <agent>                 # what an agent remembers (also: search, pin, forget)
sua usage --days 7                      # what runs cost, by agent and provider
sua policy show                         # the tool policy in force (also: check, validate)
sua behaviors list                      # Agent Behavior specs (also: show, validate)
```

### Lower-level agent tools

`sua agent run` / `sua agent list` cover every agent; `sua workflow` has the extra tools.

```bash
sua workflow list                       # agents in the store, with their nodes
sua workflow run <id>                   # execute an agent's flow
sua workflow replay <runId> --from <nodeId>  # replay from a node
sua workflow import-yaml <file>         # import a v2 YAML into the store
```

### Tools

```bash
sua tool list                           # built-in + user tools
sua tool show <id>                      # inspect inputs/outputs
sua tool validate <file>                # schema-check a tool YAML
```

### Examples

```bash
sua examples install                    # import all bundled examples
sua examples remove                     # remove example agents from DB
sua examples list                       # show install status
```

### Variables

```bash
sua vars list                           # all global variables (names + values)
sua vars get <NAME>                     # get a variable's value
sua vars set <NAME> <VALUE>             # set/update a variable
sua vars delete <NAME>                  # remove a variable
```

### Secrets

```bash
sua secrets set <NAME>                  # store an encrypted secret
sua secrets list                        # list names (values hidden)
sua secrets delete <NAME>               # remove a secret
```

### Build planner

```bash
sua planner smoke                       # dry-run preview of pipeline scenarios
sua planner smoke --live                # run all 6 server scenarios end-to-end
sua planner smoke --live --browser      # also drive 2 wizard scenarios via playwright
```

### Infrastructure

```bash
sua init                                # initialize a project
sua doctor                              # check prerequisites
sua mcp start                           # start the MCP server
sua dashboard start                     # start the web dashboard
sua dashboard signin-url                # print the dashboard sign-in link again
sua daemon start                        # run dashboard + scheduler + MCP (+ model, worker) detached
sua schedule list                       # show scheduled agents
```

## Flow control

Agents support first-class flow control nodes:

```yaml
nodes:
  - id: fetch
    type: shell
    command: echo '{"status": 200, "data": "ok"}'

  - id: check
    type: conditional
    dependsOn: [fetch]
    conditionalConfig:
      predicate: { field: status, equals: 200 }

  - id: process
    type: shell
    command: echo "Processing..."
    dependsOn: [check]
    onlyIf: { upstream: check, field: matched, equals: true }

  - id: fallback
    type: shell
    command: echo "Fetch failed"
    dependsOn: [check]
    onlyIf: { upstream: check, field: matched, notEquals: true }
```

Available node types: `conditional`, `switch`, `loop`, `agent-invoke`, `branch`, `end`, `break`.

## Security

- **Secrets encrypted at rest** — AES-256-GCM with scrypt KDF (OWASP 2024 params)
- **3-layer redaction in run logs** — declared secrets, sensitive name patterns (TOKEN, KEY, PASS), known credential value patterns (GitHub PATs, AWS keys, JWTs)
- **Path traversal protection** — file-read/file-write tools validate paths stay within the working directory
- **Env-var injection deny-list** — agent inputs cannot override LD_PRELOAD, PATH, NODE_OPTIONS, or 25+ other sensitive env vars
- **MCP binds localhost** — bearer token auth, loopback-only by default, timing-safe token comparison
- **Community shell gate** — community agents require explicit `--allow-untrusted-shell`
- **Dashboard auth** — 3-layer (Host + Origin + cookie), HttpOnly SameSite=Strict cookies; a 30-day idle session renewed as you use it (`SUA_DASHBOARD_SESSION_HOURS` to change); the chat WebSocket requires the same cookie plus an allowed Origin
- **Tool policies** — allow/deny rules checked on every tool call, failing closed if the policy file is invalid
- **CI/CD** — SHA-pinned GitHub Actions, npm Trusted Publishing via OIDC (no static NPM_TOKEN)
- **Example agents vetted** — CI security check + execution test on every PR

Full model: [docs/SECURITY.md](docs/SECURITY.md)
