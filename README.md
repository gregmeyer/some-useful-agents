# some-useful-agents

**Ask a question; get back a researched answer you can check, laid out the same clear way every time.**

sua does the legwork on your machine: it works out how to research your question, searches, reads the pages, and writes up what it found. Every claim links to its source, and each source shows the quote it rests on and whether that quote was really on the page. Each kind of answer (a shortlist, a meeting brief, a company or topic brief, an explainer, a how-to, a plan, a watch) always looks the same, so you know where to look.

Underneath is a local-first agent playground: author agents as composable flows, run them from the CLI or MCP, schedule them on cron, chain them into multi-step pipelines with branching and loops, and manage everything from a web dashboard.

MIT-licensed. Published to [npm](https://www.npmjs.com/search?q=%40some-useful-agents).

## What you get

**Agents**
- **Agents as flows** — each agent is a set of connected nodes: shell commands, `llm-prompt` model calls, named tools, `goal` nodes, and `ask` nodes. Flow control (conditional, switch, loop, agent-invoke, branch, end, break) lets agents make decisions and run sub-agents. Reference: [docs/flows.md](docs/flows.md).
- **Goal agents** — a `goal` node gives a model a goal, tools and a budget (turns, time), and it works until it can answer. Build from goal drafts one for open-ended asks. See [docs/goal-agents.md](docs/goal-agents.md).
- **Agents as tools** — put `agent:<id>` in a node's `tools:` and the model can call another agent as a sub-run (up to 3 levels deep, no cycles). See [docs/agents-as-tools.md](docs/agents-as-tools.md).
- **Conversations** — talk to any agent with a text input and follow up: the agent's **Chat** tab (replies stream in live over a WebSocket), `sua agent chat`, or MCP `run-agent` with a `sessionId`. See [docs/conversations.md](docs/conversations.md).
- **Memory** — `memory: true` gives an agent notes that persist between runs, recalled automatically, with `memory-save` / `memory-search` / `memory-forget` tools. See [docs/memory.md](docs/memory.md).
- **Ask a person** — an `ask` node, or the `ask-human` tool in an llm or goal node, pauses the run and puts the question in your inbox; answering resumes it. See [docs/ask-a-person.md](docs/ask-a-person.md).
- **Behaviors** — write down how an agent should conduct itself as an [Agent Behavior](docs/behaviors.md) spec, and optionally let it steer the agent.

**Models and tools**
- **Many providers, tried in order** — Claude, Codex, on-device Apple Foundation Models, or any **OpenAI-compatible endpoint** for local / self-hosted models (llama.cpp, LM Studio, Ollama, vLLM, …). Set the provider order and add or turn off providers at `/settings/llm`. On a classified failure (down, timeout, quota, 401, 429) a node moves on to the next provider; a provider that's down is skipped for a while, Settings → LLM shows how each one did this week, and an optional daily cap limits what's spent when the first one fails. Pin per node or agent with `provider:`. Claude and Codex get a node's `tools:` over a short-lived local MCP endpoint; OpenAI-compatible endpoints get them natively. A local model server can run as a `sua daemon` service. See [docs/llm-providers.md](docs/llm-providers.md).
- **Built-in tools** — `shell-exec`, `http-get`, `http-post`, `file-read`, `file-write`, `json-parse`, `json-path`, `template`, `csv-to-chart-json`, web fetch and scrape, `web-screenshot`, `notebook-read`, `experiment-read`, `board-read` / `board-place`, and more; plus tools imported from MCP servers, tools generated by integrations, and commands or prompts you add yourself (`sua tool add`). Every tool call is recorded on the run page. See [docs/tools.md](docs/tools.md).
- **Integrations** — connect a data source or service at `/tools?tab=integrations` and get tools for free: CSV / Postgres / SQLite generate find/count tools, Gmail connects via OAuth, and `notify` handlers can use saved Slack / webhook / file destinations. See [docs/integrations.md](docs/integrations.md).
- **MCP servers** — paste a Claude Desktop / Cursor `mcpServers` config, pick which tools to import, and runs can call them like any other tool. Manage servers at `/tools?tab=servers`. See [docs/mcp.md](docs/mcp.md).

**Control and safety**
- **Tool policies** — allow/deny rules checked on every tool call, by tool, resource (URL, path, command) and agent source. Edit and test them in **Settings → Policies** ("Would this be allowed?"). See [docs/tool-policies.md](docs/tool-policies.md).
- **Cost and spend limits** — every run records its tokens and cost; see them per run, in **Settings → Usage**, or with `sua usage`. Cap a run or an agent's day with `spendLimit: { perRunUsd, perDayUsd }`. See [docs/cost.md](docs/cost.md).
- **Secrets store** — encrypted at rest (AES-256-GCM, scrypt). Protect it with a passphrase, or use the zero-friction fallback keyed off a stable local machine key. Dashboard CRUD with redaction.
- **Run reliability** — per-node `timeout:` and agent `timeoutSec:` ceilings. Stopping a node (Cancel, a timeout, a dashboard restart) also stops everything it started; a clean shutdown ends its runs as cancelled, and a reaper cleans up after a crash. A step can **keep going if it fails** (`optional: true`, or the box on the step's Edit page), so one dead source doesn't sink a search; a loop can run its items at the same time (`loopConfig.concurrency`). See [docs/agents.md](docs/agents.md#timeouts) and [docs/SECURITY.md](docs/SECURITY.md).
- **Retries and checks** — a `retry:` policy runs a failed run again when the failure looks transient (a timeout, a command that failed to start); `successCriteria` checks what an agent produced and runs it again with feedback when it falls short; outcome detection records what a run actually changed against what was expected. See [docs/retry.md](docs/retry.md), [docs/success-criteria.md](docs/success-criteria.md) and [docs/outcome-detection.md](docs/outcome-detection.md).

**Triggers**
- **Scheduling** — cron on any agent; `/scheduled` lists every scheduled agent with Pause / Resume / Activate, and Pulse shows a red scheduler tile if agents are scheduled but the scheduler isn't running. A schedule you change, and an agent you edit, reach the next scheduled run within a minute, without a restart. A Temporal provider is available for durable runs. See [docs/temporal.md](docs/temporal.md).
- **Inbound webhooks** — start an agent from another service with `POST /hooks/<agent>`: a per-agent secret (or a GitHub signature), body-to-input mapping and filters. See [docs/webhooks.md](docs/webhooks.md).
- **MCP server (outbound)** — expose your agents to Claude Desktop and other MCP clients: run an agent or hold a conversation with it, read and arrange boards, and start and read notebooks. The full tool list is in [docs/mcp.md](docs/mcp.md).

**Answers: ask a question, get one you can check**
- **Answers** — ask in a sentence (a car to buy, a meeting to get ready for, how something works) on Home or in sua's bar, and sua works out how to research it and goes straight through: find, source, check, then decide or write it up. It stops only when it's stuck or needs you. Each answer gets the page for its kind: a **Shortlist**, a **Meeting brief**, a **Company brief** or **Topic brief**, an **Explainer**, a **How-to** to follow step by step, a **Plan** or a **Watch**. Every source is listed, and each one opens to its quote and whether the quote was found on its page. The header shows what you asked and how many sources were checked, with **Print** beside it. Ask a follow-up from the foot. Change one by saying what to change, or save it as a **template**. Give it a file or a paste (a résumé, notes) and it reads the text. In the code, the CLI and MCP they're called notebooks. See [docs/notebooks.md](docs/notebooks.md).
- **Briefings, with their sources** — "Tell me about…" a company, a person, a product or a topic, and the notebook is a briefing on it: each part cites what it rests on, says how sure it is, and lists what isn't known. See [docs/notebooks.md](docs/notebooks.md#tell-me-about-a-briefing-on-a-subject).
- **Experiments** — find out what changes what an agent produces. Give one agent the same ask under different versions of it (an earlier version against a later one, another model, another value for one of its inputs), run the whole agent a few times under each, and read how much the versions' results have in common against how much two runs of the same version do. A whole notebook can be run the same way, as a fresh copy for each version, changing its limits and checks, something you gave it, who does a step, or the model. The numbers are counted from the runs. See [docs/experiments.md](docs/experiments.md).

**Seeing results**
- **Dashboard** — manage agents, tools, runs, secrets, variables and settings in the browser. **Home** leads with **Ask a question**, then what needs you and your recent answers (Next up, today's numbers and today's reads are a Show away). The top bar is **Answers · Settings · More** (Agents, Experiments, Pulse, Help); **Pulse** (`/pulse`) opens on **Today's edition**, a front page made fresh from what your scheduled agents produced in the last day, with the board of agent tiles (each with a **Run** button) under **All agents**. A diagram editor with a wiring mode, run pages with node-by-node detail, budgets and tool calls. See [docs/dashboard.md](docs/dashboard.md).
- **Widgets, drawn with A2UI** — an agent can describe its widget as an [A2UI](https://a2ui.org) `view:` (declared in YAML, or generated by a node each run), and it's drawn on the run page, its Pulse tile, dashboards, inbox threads, and in chat: any agent's reply, and sua's own, can include a widget that draws as it streams, with buttons that work wherever the conversation is shown. **Change how this looks** on an agent's latest result asks sua to redesign it. Existing output widgets and Pulse templates are drawn the same way, with sorting, filtering, paging, tabs and run-in-place forms in the browser. See [docs/a2ui-views.md](docs/a2ui-views.md) and [docs/output-widgets.md](docs/output-widgets.md).
- **Boards as canvases** — Pulse and every dashboard are drawn as one A2UI canvas: sections, responsive grids, rows, tabs and cards, with each agent's tile drawn inside by its own view. Arrange it in an outline editor (**✎ Arrange**), let the layout planner propose one (**✨ Suggest a layout**), or let an agent do it with the `board-read` / `board-place` tools. Layouts are stored by the dashboard, versioned and undoable. A board can have a **goal**, and **Improve this board** has sua review it against that goal and suggest agents to add, leave out or draft; a board's page can also be composed like a front page from its agents' results. See [docs/boards.md](docs/boards.md).
- **Build a board from a request** — describe a board (**＋ New board**, Ask sua, or MCP `build-board`) and sua picks your agents, lays it out, runs every tile and tells you in the inbox when it's ready; agents for anything not covered are drafted and wait for your one approval. See [docs/boards.md](docs/boards.md#build-a-board-from-a-request).
- **Brand theme** — one theme for every page, board and tile: a preset, then your colours for dark and light mode, fonts, corner radius and tile accents, in **Settings → Appearance**: see the look you have now, use another from a gallery in one click, or **Fine-tune** it. See [docs/brand.md](docs/brand.md).
- **Dashboards and packs** — named boards over your agents; packs install curated agents and dashboards together (the `Starter` pack ships with sua). Browse at `/packs`.

**Building agents**
- **Build from a goal** — describe what you want and sua drafts the agents (a goal node for open-ended asks, a fixed flow for repeatable ones), shows each draft's shape and **why**, lets you switch the shape and **Try it** before keeping it. See [docs/build-from-goal.md](docs/build-from-goal.md).
- **Suggest improvements** — one-click review of an agent's YAML by the built-in `agent-analyzer`, with a diff you can apply.
- **Skills** — know-how several agents share (how to research a list, how to search the web), kept in one file; sua suggests one when it builds or fixes an agent, and shell nodes share Python helpers. See [docs/skills.md](docs/skills.md).
- **Global variables** — plain-text values every agent can use (`/settings/variables` or `sua vars`); `$NAME` in shell, `{{vars.NAME}}` in prompts.
- **40+ bundled examples** — from "hello world" to MCP-driven graphics, installed by `sua init`. The dashboard opens new users on **Start here** (`/start`): four agents, one per pattern (research something, watch something, draft something, work it out).

## Quick start

```bash
npm install -g @some-useful-agents/cli
mkdir my-agents && cd my-agents
sua init                    # creates project + installs example agents
sua agent run hello         # run your first agent
sua dashboard start         # open the web dashboard
```

Prefer `npx`? `npx @some-useful-agents/cli@latest init` works without installing globally.

## CLI commands

### Agents

```bash
sua agent list                          # all agents (examples + local)
sua agent new                           # interactive scaffold
sua agent run <name>                    # run once
sua agent run <name> --input K=V        # supply inputs (-i for short)
sua agent chat <name>                   # talk to an agent and follow up (-m "…" for one message)
sua agent webhook <name> --on           # start it from another service: POST /hooks/<name>
sua agent reimport <path>               # refresh agent(s) in DB from on-disk YAML
```

### Inspecting runs

```bash
sua agent status                        # recent runs, newest first
sua agent logs <runId>                  # one run's output
sua agent cancel <runId>                # stop a run (and everything its nodes started)
sua outcome list                        # recent outcome records: what was expected, what resulted
```

### Memory, cost and policies

```bash
sua memory list <agent>                 # what an agent remembers (also: search, pin, forget)
sua usage --days 7                      # what runs cost, by agent and provider
sua policy show                         # the tool policy in force (also: check, validate)
sua behaviors list                      # Agent Behavior specs (also: show, validate)
```

### Lower-level agent tools

`sua agent run` / `sua agent list` cover every agent; `sua workflow` has the extra tools.

```bash
sua workflow list                       # agents in the store, with their nodes
sua workflow run <id>                   # execute an agent's flow
sua workflow replay <runId> --from <nodeId>  # replay from a node
sua workflow import-yaml <file>         # import an agent YAML file into the store
```

### Tools

```bash
sua tool list                           # built-in tools and yours
sua tool show <id>                      # inspect inputs/outputs
sua tool validate <file>                # schema-check a tool YAML
sua tool add <file>                     # add (or update) a tool you made: a command or a prompt
sua tool remove <id>                    # remove a tool you added
```

### Examples

```bash
sua examples install                    # import all bundled examples
sua examples remove                     # remove example agents from DB
sua examples list                       # show install status
```

### Variables

```bash
sua vars list                           # all global variables (names + values)
sua vars get <NAME>                     # get a variable's value
sua vars set <NAME> <VALUE>             # set/update a variable
sua vars delete <NAME>                  # remove a variable
```

### Secrets

```bash
sua secrets set <NAME>                  # store an encrypted secret
sua secrets list                        # list names (values hidden)
sua secrets delete <NAME>               # remove a secret
```


### Infrastructure

```bash
sua init                                # initialize a project
sua mcp start                           # start the MCP server
sua dashboard start                     # start the web dashboard
sua dashboard signin-url                # print the dashboard sign-in link again
sua daemon start                        # run dashboard + scheduler + MCP (+ model, worker) detached
sua schedule list                       # show scheduled agents
```

### Upkeep

```bash
sua doctor                              # prerequisites, file permissions, how each model provider did
sua daemon status                       # which services are running (also: restart, stop, logs)
sua db compact                          # store repeated run inputs once, then shrink the database
sua backups prune --dry-run             # old database backups (checkout installs; see CONTRIBUTING.md)
```

`sua <command> --help` lists every subcommand, and the dashboard's **Help** page lists them by what they're for.

## Flow control

Agents support first-class flow control nodes:

```yaml
nodes:
  - id: fetch
    type: shell
    command: echo '{"status": 200, "data": "ok"}'

  - id: check
    type: conditional
    dependsOn: [fetch]
    conditionalConfig:
      predicate: { field: status, equals: 200 }

  - id: process
    type: shell
    command: echo "Processing..."
    dependsOn: [check]
    onlyIf: { upstream: check, field: matched, equals: true }

  - id: fallback
    type: shell
    command: echo "Fetch failed"
    dependsOn: [check]
    onlyIf: { upstream: check, field: matched, notEquals: true }
```

Available node types: `conditional`, `switch`, `loop`, `agent-invoke`, `branch`, `end`, `break`.

## Security

- **Secrets encrypted at rest** — AES-256-GCM with scrypt KDF (OWASP 2024 params)
- **3-layer redaction in run logs** — declared secrets, sensitive name patterns (TOKEN, KEY, PASS), known credential value patterns (GitHub PATs, AWS keys, JWTs)
- **Path traversal protection** — file-read/file-write tools validate paths stay within the working directory
- **Env-var injection deny-list** — agent inputs cannot override LD_PRELOAD, PATH, NODE_OPTIONS, or 25+ other sensitive env vars
- **MCP binds localhost** — bearer token auth, loopback-only by default, timing-safe token comparison
- **Community shell gate** — community agents require explicit `--allow-untrusted-shell`
- **Dashboard auth** — 3-layer (Host + Origin + cookie), HttpOnly SameSite=Strict cookies; a 30-day idle session renewed as you use it (`SUA_DASHBOARD_SESSION_HOURS` to change); the chat WebSocket requires the same cookie plus an allowed Origin
- **Tool policies** — allow/deny rules checked on every tool call, failing closed if the policy file is invalid
- **CI/CD** — SHA-pinned GitHub Actions, npm Trusted Publishing via OIDC (no static NPM_TOKEN)
- **Example agents vetted** — CI security check + execution test on every PR

Full model: [docs/SECURITY.md](docs/SECURITY.md)

- Docker (optional, for Temporal or docker-stdio MCP servers)
