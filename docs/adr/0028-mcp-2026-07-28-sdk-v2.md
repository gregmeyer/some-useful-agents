# ADR-0028: MCP 2026-07-28 migration — stateless server + SDK v2 on both sides

## Status

Accepted (shipped in #600 inbound server, #601 outbound client). Supersedes the
stateful-session parts of [ADR-0003](0003-mcp-http-sse-transport.md) (the HTTP
transport choice itself still holds).

## Context

MCP shipped its [2026-07-28 revision](https://blog.modelcontextprotocol.io/posts/2026-07-28/),
the largest since launch. The load-bearing change for us is a **stateless
protocol core**: no `initialize` handshake, no `Mcp-Session-Id`, no
server-held session state. It ships as a new **v2 TypeScript SDK split into
`@modelcontextprotocol/server` + `@modelcontextprotocol/client`** (the old
`@modelcontextprotocol/sdk` v1 line stays for 2025-era peers), and a single v2
handler can serve both 2025-era and 2026-07-28 clients side by side.

We had two MCP subsystems, both on `@modelcontextprotocol/sdk@1.30.0`:

- **Inbound server** (`packages/mcp-server`) exposing our agents to Claude
  Desktop/Cursor. It was stateful *only* to work around v1's 1:1
  server↔transport coupling: an in-memory session `Map`, a minted
  `Mcp-Session-Id`, and a per-session `sha256(token)` binding.
- **Outbound client** (`packages/core/src/mcp-client.ts`) consuming external
  MCP servers as agent tools and `mcp-tool` notify destinations.

A de-risk spike against the real v2.0.0 packages confirmed the key facts before
we committed: the `node:http` bridge is a provided one-liner (`toNodeHandler`,
no custom shim); `legacy:'stateless'` genuinely serves both eras (a v1 client
works against the stateless v2 server); registration is
`registerTool(name, {description, inputSchema}, handler)` and accepts Zod v4
raw shapes directly.

## Decision

1. **Inbound server → stateless SDK v2.** Replace the session model with
   `toNodeHandler(createMcpHandler(factory, { legacy: 'stateless' }))`, bridged
   into our existing `node:http` shell. `createMcpHandler` builds a fresh
   `McpServer` per request, so the session `Map`, `Mcp-Session-Id`, and
   `tokenHash` binding are deleted. Our custom loopback Host/Origin +
   shared-bearer auth gate runs in the `node:http` handler **before** delegating;
   `/health` and `port:0` handling are preserved. `legacy:'stateless'` keeps
   serving existing 2025-era clients (e.g. installed Claude Desktop) over the
   same `/mcp` endpoint — no client config change.

2. **Outbound client → SDK v2 with `versionNegotiation:'auto'`.** One pooled
   client transparently talks to both 2025-era and 2026-07-28 external servers.
   Caller surface (`callMcpTool`/`listMcpTools`), pooling, and transports are
   unchanged. We keep the SDK's non-fulfilling `inputRequired` default: agent
   tool calls are non-interactive, so a server demanding mid-call input errors
   rather than hanging a DAG node.

3. **Tasks extension: deferred, not adopted.** The 2026-07-28 Tasks extension is
   a natural fit for our long-running runs, but the v2.0 TS SDK ships Tasks as
   *wire vocabulary with no runtime* — `tasks/get`/`tasks/update`/`tasks/cancel`
   are excluded from the registrable method surface, and the SDK's own
   conformance suite skips tasks. Adopting Tasks would require hand-rolling raw
   JSON-RPC outside the SDK's typed surface. We defer it until the SDK provides a
   task runtime rather than take on an unsupported code path.

## Consequences

**Easier / better:**
- The inbound server scales behind ordinary HTTP infrastructure — no session
  affinity, no shared session store.
- A large amount of workaround code (session map, id minting, token-to-session
  binding, per-session server lifecycle) is deleted.
- Both MCP subsystems are on one SDK generation; core no longer depends on the
  v1 SDK at runtime.

**Security (deliberate behavior change):**
- The per-session token binding — which stopped a rotated token from hijacking a
  live session — is **removed**, because a stateless protocol has no live
  session to hijack. Every request re-runs the full Host/Origin + bearer check
  fresh. The loopback defenses and single shared-bearer model are otherwise
  unchanged. Reviewed under `/security-review`.

**Trade-offs accepted:**
- No Tasks/Resources/cacheable-list features this pass (Resources and cache
  hints are supported by the SDK and can be added later; Tasks waits on SDK
  runtime support).
- `@modelcontextprotocol/sdk@1.30.0` remains as an mcp-server **devDependency**
  only, to drive the 2025-era back-compat test.
