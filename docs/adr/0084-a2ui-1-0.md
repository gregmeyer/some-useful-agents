# ADR-0084: A2UI 1.0

- Status: accepted
- Date: 2026-11-20
- Deciders: Greg Meyer
- Amends: ADR-0047 (its protocol version and vendored renderer)

## Context

ADR-0047 drew views with A2UI v0.9.1. The browser used `@a2ui/lit` and `@a2ui/web_core` 0.12, vendored as one module, and the server validated with `@a2ui/web_core`. A Dependabot bump had moved the server to 0.15, so the two had drifted apart, against ADR-0047's rule that they match.

Google released A2UI 1.0. It brings:
- `createSurface` that carries its components and data;
- typed `@path` / `@call` bindings;
- `@checks` validation that disables a button until a form is valid;
- function calls in both directions, mixed catalogs, and `@accessibility`.

The 1.0 web renderer is on the A2UI repo's main branch (`web_core` and `lit` 0.16), but not yet on npm. On npm, `@a2ui/lit` 0.15 draws only 0.9, and `web_core` 0.15 is an earlier take on 1.0 that still uses `checks`.

## Decision

**Draw and validate with A2UI 1.0, vendored from the A2UI repo at a pinned commit.**

- **One build for both sides.** `packages/dashboard/scripts/vendor-a2ui.mjs`:
  - clones a2ui-project/a2ui at `A2UI_COMMIT`;
  - builds `web_core` and `lit`;
  - writes two bundles, each stamped with the commit: `dashboard/src/assets/vendor/a2ui-v1_0.js` for the browser, and `core/vendor/a2ui-web-core-v1.mjs` for Node.
- **What core uses.** Core imports the processor, the catalog class, the 1.0 common schemas and zod from its bundle, and ships `vendor/` with the package. The npm `@a2ui/web_core` dependency is gone.
- **The drift can't recur.** A test checks that the two bundles name the same commit.
- **When 0.16 reaches npm**, the script can install it from there instead.
- **The sua catalog** is a 1.0 catalog (`Catalog(SUA_CATALOG_ID, '1.0', …)`) with the 1.0 basic components.
  - Our components keep their schemas: every `CommonSchemas` name they use exists in 1.0, and 1.0's `@`-keys come with `ComponentCommon`.
  - They render on 1.0's element, which keeps `controller.props` and `renderNode`.
- **v0.9 still draws.** `normalizeComponents` (core) rewrites what 1.0 refuses:
  - a Text `variant` of h1–h5 becomes a markdown heading;
  - a TextField's `validationRegexp` becomes a `regex` check;
  - an id that isn't a UAX #31 identifier, such as one with a hyphen, is renamed, and every `child`, `children`, `componentId`, `trigger` or `content` reference to it follows.
- **Rewritten only at the boundary.** `componentsForRender` also turns bindings into their 1.0 form (`path`→`@path`, `call`→`@call`, `checks`→`@checks`; a template's `{path, componentId}` stays). It runs only on what is sent to the browser (`viewToMessages`, the board canvas). It is needed because 1.0 still validates `{path}` but draws only `{"@path"}`.
  - Validation checks the drawn form, and the server keeps working with layouts as stored.
  - The model guides keep teaching the v0.9 form for now.
- **Generated ids are valid at the source.** The Pulse "Everything else" ids are built with `a2uiId`, so the canvas editor and the drawn page agree on every id.

## Consequences

- Every saved layout on the live install validates as 1.0: 31 notebook pages, 6 boards, the 7 notebook presets and 10 agent views. A notebook page and Pulse draw the same as before.
- The browser bundle grows from 332 KB to 512 KB.
- We run unreleased A2UI code, pinned. A bug there is ours until we move the pin; the server and browser at least always agree.
- The way is open for what 1.0 adds:
  - incremental `updateComponents` and per-path data updates;
  - one action channel, and forms with `@checks`;
  - renderer and agent functions;
  - the `vegachart` catalog, and surfaces over MCP.
- **Not done here:** teaching models `@path` (the guides) and publishing the sua catalog as a 1.0 catalog document.
